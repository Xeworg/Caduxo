## Key Learnings

1. The typesafe-i18n `npm run i18n:generate` "all files are up to date" message is the authoritative EN/ES parity gate; this slice added 11 keys (1 common + 8 dashboard.aria + 1 reports.table + 1 categoryPicker) and the generator confirmed both trees are complete with non-empty strings.
2. The pi-lens embedded LSP diagnostic server holds a stale i18n-types.ts snapshot independent of the typesafe-i18n generator output; live `tsc`, `svelte-check`, and `vite build` always supersede the snapshot for verification purposes.
3. The reuse of `$LL.products.pageTitle()` ("Products" / "Productos") for the DashboardPage "Product detail" modal is a defensible exception that avoids introducing a duplicate aria string, and matches the spec's intent (replace the hardcoded English aria label, not enforce a strict pageTitle↔ariaLabel mapping).
4. A grep-based sweep for hardcoded `aria-label="<Capitalized>"` literals across `src/` is a reliable way to detect English-only aria residue because the parent English labels are sentence-case and would otherwise slip past case-insensitive rules.
5. The `dashboard.aria` namespace is the conventional home for section-level aria labels in this codebase (8 keys added in this slice, all under the same sub-tree), which keeps the translator's mental model flat and predictable.
