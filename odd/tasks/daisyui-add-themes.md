# DaisyUI additional themes

## Goal
Add a curated set of DaisyUI built-in themes for visual testing and user selection without enabling the full theme catalog.

## Selected themes
Keep existing:
- `caduxo-light`
- `dark`

Add:
- `dracula`
- `valentine`
- `luxury`
- `sunset`
- `nord`

## Evidence

### Frontend wiring
- `src/app.css` — DaisyUI v5 plugin block updated:
  `themes: caduxo-light --default, dark, dracula, valentine, luxury, sunset, nord;`
  `caduxo-light --default` is preserved; `themes: all` is intentionally NOT used.
- `src/lib/stores.ts` — `ThemeName` union extended with the five new names.
- `src/components/ui/theme/themeStore.svelte.ts` — `AVAILABLE_THEMES` array
  extended in the same order, with the first entry kept as the default.
- `src/components/ConfigurationPage.svelte` — `themeLabel()` switch now
  exhausts every `ThemeName` variant (a future theme addition triggers a
  TS error here until the matching i18n key is added).
- `src/i18n/en/index.ts` & `src/i18n/es/index.ts` — added labels for
  `dracula`, `valentine`, `luxury`, `sunset`, `nord` under the top-level
  `theme` namespace.
- `src/i18n/i18n-types.ts` — regenerated via `npm run i18n:generate`; the
  new keys are present in the auto-generated `Translation` and runtime
  `TranslationFunctions` shapes.

### Backend wiring
- `src-tauri/src/services/user_messages.rs` — owns the canonical
  `pub const ALLOWED_THEMES: &[&str]` (the 7-theme list in display
  order) and `pub const ALLOWED_THEMES_DISPLAY` (the comma-joined form
  used inside the rejection message). Both the English and Spanish
  `ThemeNotAllowed` strings and the `parse_theme_not_allowed` parser
  are now driven by these constants.
- `src-tauri/src/commands/stores.rs` — imports `ALLOWED_THEMES` from
  `user_messages`; `validate_theme_value` consults the shared constant so
  the IPC boundary cannot drift away from the user-facing message.
- `src-tauri/src/db/repositories/settings.rs` — `get_settings` snapshot
  derives `theme_configured` from `ALLOWED_THEMES` (so a persisted
  `dracula` row is now honoured as a manual preference instead of
  silently falling back to `"caduxo-light"` with `theme_configured: false`).

### Tests
- `commands/stores.rs::tests` — added acceptance tests for each of the
  five new themes (English + Spanish coverage) and a case-sensitivity
  regression for uppercase `Dracula`. Kept `synthwave` as the rejection
  sample (real DaisyUI theme, intentionally NOT in the curated set, so
  swapping for `themes: all` coverage would visibly break this test).
  All literal-message assertions now go through
  `ALLOWED_THEMES_DISPLAY` so the list stays single-sourced.
- `db/repositories/settings.rs::tests` —
  `get_settings_theme_configured_when_persisted` now iterates over all
  seven themes so the snapshot recognises every curated name.
  `get_settings_theme_unconfigured_for_unsupported_value` still uses
  `synthwave` (outside the curated set) so the rejection path stays
  covered.

  the five new theme keys.
- `npm run check` → `svelte-check found 0 errors and 0 warnings`.
